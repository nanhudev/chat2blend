# Security

Chat2Blend executes LLM-generated Python inside Blender. That is its purpose. We do not pretend this is a sandbox.

## What Chat2Blend can and cannot do

- It can run any Python the LLM produces.
- It cannot protect you from a malicious or tricked LLM.
- It does not read your ChatGPT credentials or browser cookies.

## Network model

- The bridge binds **127.0.0.1 only**.
- It rejects requests whose TCP source is not loopback.
- It rejects `Origin` headers from web pages that are not `chrome-extension://`, `http://127.0.0.1`, or `http://localhost`.
- `0.0.0.0` binding is not implemented and not allowed.

## Authentication

- The bridge starts with a long random token stored in the OS app data directory (`%APPDATA%\chat2blend` on Windows, `~/Library/Application Support/chat2blend` on macOS, `~/.config/chat2blend` on Linux).
- The browser extension cannot talk to the bridge until it pairs with a 6-digit code generated by `c2b pair`.
- Pairing codes time out after 10 minutes and rotate on each use.
- All endpoints except `/health` and `/api/pair` require the token in the `X-C2B-Token` header.

## Credential hygiene

- No API keys, tokens, or browser cookies are committed to Git. `.gitignore` excludes `.state/`, `logs/`, and `*.log`.
- The bridge token is local to one machine.

## Best practices

- Keep the bridge stopped when you do not need it.
- Only load the extension from `apps/extension/dist` built from this repository.
- Do not run Chat2Blend on a shared or untrusted machine.
- Review LLM-generated code before turning Auto Execute ON for untrusted models.

## Reporting issues

If you find a security problem, please open an issue or email the maintainer.
